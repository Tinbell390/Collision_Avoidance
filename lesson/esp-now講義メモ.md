# ESP-NOWとは？

* Espressif社が開発した無線通信プロトコル
* Wi-Fiの物理層・MAC層を利用
* APやルータを介さず、端末間で直接通信

> ESP-NOWは、Espressif社が開発した無線通信プロトコルです。
>
> 通常のWi-Fi通信では、アクセスポイントやルータを介して通信しますが、ESP-NOWでは端末同士が直接通信できます。
>
> Wi-Fiの電波を利用しますが、IPアドレスやTCP・UDPなどを使った一般的なネットワーク通信とは異なります。

---

# ESP-NOWの特徴

* **Wi-Fiを利用した端末間通信**
* **AP・ルータ不要**
* **MACアドレスを用いて通信相手を指定**
* **送信データはバイト列**
* **送受信時にコールバック関数を利用**

> ESP-NOWでは、通信相手をMACアドレスで指定します。
>
> また、送信するデータは基本的にバイト列として扱います。そのため、整数や構造体などを送信する場合も、最終的にはバイト列として扱うことになります。
>
> 受信時には、データを受け取ったタイミングであらかじめ登録したコールバック関数が呼び出されます。

---

# 通常のWi-Fi通信との違い

| 通常のWi-Fi通信     | ESP-NOW     |
| -------------- | ----------- |
| AP・ルータを介して通信   | 端末間で直接通信    |
| IPアドレスを利用      | MACアドレスを利用  |
| TCP / UDPなどを利用 | MAC層の仕組みを利用 |
| ネットワーク通信       | 低レイヤの通信     |

> 普段Webページを見るときなどは、Wi-Fiでアクセスポイントに接続し、IPアドレスを使って通信します。
>
> ESP-NOWは、こうしたネットワーク層以上の仕組みを使わず、より低いレイヤで端末同士が直接通信します。
>
> そのため、通信処理を比較的シンプルに構成できます。

# OSI参照モデルとESP-NOW

```text
┌────────────────────┐
│  7. アプリケーション層 │
├────────────────────┤
│  6. プレゼンテーション層│
├────────────────────┤
│  5. セッション層       │
├────────────────────┤
│  4. トランスポート層   │
├────────────────────┤
│  3. ネットワーク層     │
├────────────────────┤
│  2. データリンク層     │ ← ESP-NOW
├────────────────────┤
│  1. 物理層             │ ← Wi-Fiを利用
└────────────────────┘
```

* ESP-NOW：**Wi-FiのMAC層を利用**
* Wi-Fi：**物理層を利用**
* IP / TCP / UDPは使用しない

> OSI参照モデルでは、通信の機能を7つの層に分けて考えます。
>
> ESP-NOWは、主にデータリンク層に相当するMAC層の仕組みを利用します。
>
> 一方、実際の無線通信にはWi-Fiの物理層を利用しています。
>
> したがって、ESP-NOWは「Wi-Fiを使っているが、通常のWi-Fiネットワーク通信とは異なる低レイヤの通信」と考えると分かりやすいです。

---

# ESP-NOW通信の基本構成

```text
ESP32 A                         ESP32 B
┌─────────┐                    ┌─────────┐
│ ESP-NOW │ ──── データ ────→ │ ESP-NOW │
└─────────┘                    └─────────┘
     │                              │
     └── MACアドレスで相手を指定 ──┘
```

* 通信相手を **Peer** として登録
* PeerのMACアドレスを指定
* 登録したPeerとデータを送受信

> ESP-NOWでは、通信相手をPeerとして管理します。
>
> Peerには通信相手のMACアドレスなどの情報を登録しておき、その情報をもとに通信相手を指定します。
>
> つまり、ESP-NOWの通信では「誰に送るのか」をMACアドレスを使って指定することが重要になります。

---

# Peerとは？

* ESP-NOWで通信する相手
* Peer情報としてMACアドレスなどを登録
* 登録したPeerに対してデータを送信

> Peerは、簡単に言えば「ESP-NOWで通信する相手」です。
>
> ESP-NOWでは、通信相手のMACアドレスなどをPeer情報として登録しておきます。
>
> これによって、送信時にどの端末へデータを送るかを指定できます。

---

# 送信データ

* データは **バイト列**として送信
* `uint8_t` の配列として扱う
* **送信できるデータサイズは250Bが上限**

```cpp
uint8_t data[] = {
    10, 20, 30
};
```

> ESP-NOWで送信するデータは、バイト列として扱います。
>
> Arduinoでは、1バイトの符号なし整数である`uint8_t`を使って表現できます。
>
> 例えば、センサ値や構造体などを送信する場合も、最終的にはメモリ上のデータをバイト列として送信します。
>
> また、一度に送信できるデータサイズには上限があります。そのため、大きなデータを自由に送れる通信方式ではありません。

---

# 受信コールバック関数

* データを受信したときに自動的に呼び出される
* 受信データは **バイト列(uint8_t)**
* コールバック関数で受信処理を行う

```cpp
void OnDataRecv(
    const uint8_t *mac,
    const uint8_t *data,
    int len
)
{
    // 受信処理
}
```

> コールバック関数とは、「あるイベントが発生したら、この関数を呼び出してください」とあらかじめ登録しておく関数です。
>
> ESP-NOWでは、データを受信すると受信コールバック関数が呼び出されます。
>
> コールバック関数には、送信元の情報や受信したデータ、データサイズなどが渡されます。
>
> ここでも受信データはバイト列として渡されるため、必要に応じて元のデータ型に変換して利用します。

---

# ESP-NOWの処理の流れ

```text
Wi-Fi設定
   ↓
ESP-NOW初期化
   ↓
Peer登録
   ↓
コールバック登録
   ↓
データ送受信
```

> ESP-NOWを使用する基本的な流れは、まずWi-Fiの設定を行い、その後ESP-NOWを初期化します。
>
> 次に通信相手となるPeerを登録し、受信時に呼び出すコールバック関数を登録します。
>
> その後、Peerに対してデータを送信したり、受信コールバックでデータを処理したりします。

---

# 今回使用する関数

| 関数・型                         | 役割          |
| ---------------------------- | ----------- |
| `WiFi.mode()`                | Wi-Fiモードを設定 |
| `esp_now_init()`             | ESP-NOWを初期化 |
| `esp_now_peer_info_t`        | Peer情報を保持   |
| `esp_now_add_peer()`         | Peerを登録     |
| `esp_now_register_recv_cb()` | 受信コールバックを登録 |

> ここからは、実際にESP-NOWを使用するための主な関数について説明します。
>
> それぞれ「何をする関数なのか」「主な引数」「主な返り値」を確認します。

---

# `WiFi.mode()`

**役割**

* Wi-Fiインターフェースのモードを設定

**主な引数**

* `WIFI_STA`
* `WIFI_AP`
* `WIFI_AP_STA`

**主な返り値**

* なし

```cpp
WiFi.mode(WIFI_STA);
```

> `WiFi.mode()`は、ESP32のWi-Fiモードを設定する関数です。
>
> 今回のESP-NOWではWi-FiインターフェースをSTAモードとして設定する例を使用します。
>
> STAはStation、APはAccess Pointを意味します。
>
> ここではESP-NOWそのものよりも、「Wi-Fiの動作モードを設定する関数」として理解しておけば十分です。

---

# `esp_now_init()`

**役割**

* ESP-NOWを初期化

**主な引数**

* なし

**主な返り値**

* `ESP_OK`：成功
* その他：失敗

```cpp
if (esp_now_init() != ESP_OK) {
    // 初期化失敗
}
```

> `esp_now_init()`はESP-NOWを使用するための初期化を行います。
>
> 引数はありません。
>
> 返り値によって初期化に成功したかどうかを確認できます。
>
> ESP-NOWを使用する前に呼び出す必要があります。

---

# `esp_now_peer_info_t`

**役割**

* Peerの情報を保持する構造体

**主な情報**

* 通信相手のMACアドレス
* 暗号化などのPeer設定

```cpp
esp_now_peer_info_t peerInfo = {};
```

> `esp_now_peer_info_t`は関数ではなく、Peerの情報を格納するための構造体です。
>
> この構造体に通信相手のMACアドレスなどを設定して、Peer登録関数に渡します。
>
> 具体的なメンバについては、今回必要な範囲だけ扱います。

---

# `esp_now_add_peer()`

**役割**

* Peerを登録

**主な引数**

* `esp_now_peer_info_t`へのポインタ

**主な返り値**

* `ESP_OK`：成功
* その他：エラー

```cpp
esp_now_add_peer(&peerInfo);
```

> `esp_now_add_peer()`は、先ほど説明したPeer情報をESP-NOWに登録する関数です。
>
> 引数には`esp_now_peer_info_t`のアドレスを渡します。
>
> Peer登録が成功したかどうかは返り値で確認できます。
>
> つまり、「通信相手の情報を用意する」→「この関数で登録する」という流れになります。

---

# `esp_now_register_recv_cb()`

**役割**

* 受信コールバック関数を登録

**主な引数**

* 受信時に呼び出すコールバック関数

**主な返り値**

* バージョンによって異なるため、使用環境のAPI仕様を確認

```cpp
esp_now_register_recv_cb(OnDataRecv);
```

> `esp_now_register_recv_cb()`は、ESP-NOWでデータを受信したときに呼び出すコールバック関数を登録します。
>
> 引数として、先ほど説明した受信コールバック関数を渡します。
>
> これによって、受信イベントが発生したときに自動的に受信処理が実行されます。

---

# ESP-NOWの全体像

```text
┌──────────────────────┐
│      Wi-Fi設定       │
│    WiFi.mode()       │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│   ESP-NOW初期化      │
│   esp_now_init()     │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│      Peer登録        │
│ esp_now_add_peer()   │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│  受信CB登録           │
│ register_recv_cb()   │
└──────────┬───────────┘
           ↓
      データ送受信
```

> ESP-NOWの基本的な構成をまとめると、このようになります。
>
> Wi-Fiの設定を行い、ESP-NOWを初期化します。
>
> その後、通信相手をPeerとして登録し、受信時のコールバック関数を登録します。
>
> この一連の処理を理解しておけば、用意した基本コードを読むときにも、それぞれの処理が何を目的としているのか追いやすくなります。

---

# まとめ

* ESP-NOWは**Wi-Fiを利用した低レイヤの端末間通信**
* 通信相手は**PeerとしてMACアドレスを登録**
* データは**バイト列として送受信**
* 受信時は**コールバック関数**で処理
* 主な処理：**初期化 → Peer登録 → コールバック登録 → 通信**

> ESP-NOWでは、通常のWi-Fi通信で使うIPやTCP・UDPなどを介さず、より低いレイヤで端末間通信を行います。
>
> そのため、今回の内容では「Peer」「バイト列」「コールバック」という3つの考え方を押さえることが重要です。
>
> APIについては、それぞれの関数がどの処理を担当しているのかを対応付けて覚えておけば、基本コードを読む際に理解しやすくなります。
