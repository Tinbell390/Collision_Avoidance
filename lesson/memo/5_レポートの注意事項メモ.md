## 1. 全体構成

レポートの流れは以下のとおりです。

- 実験機器・試料
- 実験(2.1 ESP-NOW、2.2 車両制御器、2.3 衝突回避)
- 考察
- 付録

## 2. 実験機器・試料
ESP32の製造番号には**MACアドレス**を使います。
取得方法は、`env:test` を書き込み、`monitor/exp0_monitor.py` で` HELLO` を送って表示された MAC を控える、という手順です。
使用した車両・モニタ用マイコンごとに MAC を記載します。
## 3. 実験ごとの記載事項
### 3.1 ESP-NOW
穴埋めを行った `esp-now/main.cpp` を全体で付録に載せます。
通信結果(PING・DATA_REQ の成否)を示します。
前後の比較から、通信できたか否かを明記します。
シリアルモニタのログを掲載します。
### 3.2 車両制御器
付録には `calculate_pid_pwm` **関数のみ**を載せます。全体は不要です。
設計した Kp, Ki, Kd を示します。
速度応答グラフ(目標速度 vs 実速度)を載せます。
評価の観点は、立ち上がり、整定、オーバーシュート、定常偏差、振動です。
ゲインをどう変更し、応答がどう変わったかも書きます。
図は `tool/exp2_analysis.py` が `output/<時刻>/figure/` に自動生成します。速度・PWM、誤差、MAE/RMSE、整定時間、オーバーシュートも出力される。
### 3.3 衝突回避
結果を2種類に分けます。**グラフ3種(速度プロファイル、交差点占有区間タイムライン、ネゴシエーション結果)をそれぞれ載せ、個別に評価する**点を強調してください。

- 結果1: 衝突制御(collision flag = ON)
- 結果2: 衝突回避制御(collision flag = OFF)

使うグラフは `exp3_analysis.py` の次の図です。

| 求められるグラフ      | 対応する出力                                           |
| ------------- | ------------------------------------------------ |
| 速度プロファイル      | 01_speed_profile.png(02の追従誤差も補助的に使える)            |
| 交差点占有区間タイムライン | 05_timeline_gantt.png                            |
| ネゴシエーション結果    | 06_negotiation_order.png と report.md の回数・順序入替・間隔 |
- 衝突の有無は、report.md の「退出→進入の間隔」(負なら重複=衝突)で判断できます。
- ON/OFF は別々の走行なので、**出力フォルダも2つ**になります。どちらが結果1・結果2かを取り違えないよう注意させます。
## 4. 考察
課題1と2で**合計1ページ以上**記述します。
課題3(モータ評価)は任意で、追加実験を行わなければ不要です。
参考文献はそれぞれ1つ以上使用してください．十分な信頼性があればwebのものであっても問題ありません．
## 5. 説明時の注意点・よくあるミス
ログ・解析結果は`log/` と `output/` に保存されます。
図中の文字は英語表記です。日本語の説明は本文側で補うようにしてください。
グラフは貼るだけでなく、**何を読み取ったか**を書くようにしてください。
結果1(衝突)は「衝突が起きること」の確認が目的で、失敗ではありません。結果2との**対比**で評価してください。
