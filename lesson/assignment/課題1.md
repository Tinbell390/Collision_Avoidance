# ESP-NOW通信確認実験 教員向け説明書

## 1. 実験の概要

本プログラムは、ESP32間で **ESP-NOW** を利用した無線通信が正常に行えるかを確認するための実験用プログラムです。

学生には、プログラム中の4か所の穴埋めを通して、以下のC++およびESP-NOWの基本事項を確認させます。

- ESP-NOWのPeer登録
- MACアドレスの配列コピー
- 構造体をバイト列として送信する方法
- ポインタとメンバアクセス演算子（`.` / `->`）
- 受信したバイト列を構造体として解釈する方法

---

## 2. プログラム全体の構成

プログラムでは、ESP-NOWで扱うパケットを以下のように定義しています。

### 2.1 パケット種別

```cpp
enum class PacketType : uint8_t{
    HELLO,
    PING,
    PONG,
    DATA_REQ,
    DATA
};
```

各パケットの先頭に `PacketHeader` を置き、`type` によって受信処理を分岐します。

| 種別 | 役割 |
|---|---|
| `HELLO` | ブロードキャストによる通信確認 |
| `PING` | 相手への疎通確認・RTT測定開始 |
| `PONG` | PINGに対する応答 |
| `DATA_REQ` | 相手にデータ送信を要求 |
| `DATA` | ダミーの状態データを送信 |

---

## 3. パケット構造

### 3.1 ヘッダ

```cpp
struct PacketHeader{
    PacketType type;
};
```

すべてのパケットが最初に持つ共通情報です。

### 3.2 ヘッダのみのパケット

```cpp
struct Packet{
    PacketHeader header;
};
```

`HELLO`、`PING`、`PONG`、`DATA_REQ` で使用します。

### 3.3 データパケット

```cpp
struct DataPacket{
    PacketHeader header;
    StatusData payload;
};
```

`DATA` パケットでは、ヘッダに加えて `StatusData` 型のデータ本体を持ちます。

`StatusData` は `config.hpp` で定義されていることを前提としています。

# 5. 穴埋め問題の解答

## ① Peer登録・MACアドレスの扱い

### 正解

**1.**

```cpp
memcpy(peer_info.peer_addr, mac_addr, 6);
```

### 完成形

```cpp
esp_now_peer_info_t peer_info = {};

// MACアドレスをpeer_infoにコピー
memcpy(peer_info.peer_addr, mac_addr, 6);

peer_info.channel = 0;
peer_info.encrypt = false;
```

### 解説

`peer_info.peer_addr` と `mac_addr` は、どちらも6バイトのMACアドレスを格納する配列です。

```cpp
uint8_t mac_addr[6];
```

MACアドレスは例えば次のような6バイトのデータです。

```text
AA:BB:CC:DD:EE:FF
```

C++では配列同士を `=` で直接コピーすることはできません。そのため、メモリ領域の内容をコピーする `memcpy()` を使用します。

```cpp
memcpy(コピー先, コピー元, コピーするバイト数);
```

したがって、

```cpp
memcpy(peer_info.peer_addr, mac_addr, 6);
```

となります。

### 他の選択肢が不適切な理由

#### 2. `peer_info.peer_addr = mac_addr`

配列に対して代入演算子 `=` を使用しているため不適切です。

#### 3. `strcpy(peer_info.peer_addr, mac_addr)`

`strcpy()` はC言語の文字列をコピーするための関数です。

MACアドレスは文字列ではなく、`uint8_t` の6バイトデータとして扱っているため適切ではありません。

#### 4. `*peer_info.peer_addr = *mac_addr`

先頭の1バイトしかコピーされません。

# 6. ② ESP-NOWでのデータ送信

### 正解

**1.**

```cpp
reinterpret_cast<uint8_t *>(&packet)
```

### 完成形

例えば `send_hello()` では、

```cpp
if(esp_now_send(
    broadcast_address,
    reinterpret_cast<uint8_t *>(&packet),
    sizeof(packet)
) == ESP_OK){
    Serial.println("Send : HELLO");
}
```

とします。

同様に、`send_ping()`、`send_pong()`、`send_data_request()`、`send_data()` でも使用します。

### 解説

`esp_now_send()` の基本的な形式は、

```cpp
esp_now_send(
    宛先MACアドレス,
    送信データへのポインタ,
    データサイズ
);
```

です。

構造体 `packet` は、

```cpp
Packet packet;
```

のように宣言されています。

`&packet` は `Packet` 型のオブジェクトが置かれているメモリアドレスです。

ESP-NOWには、この構造体をそのまま渡すのではなく、**メモリ上のバイト列として渡す**必要があります。

そのため、

```cpp
reinterpret_cast<uint8_t *>(&packet)
```

として、`Packet` 型へのポインタを `uint8_t*` に変換します。

### なぜ `reinterpret_cast` なのか

`reinterpret_cast` は、ある型のポインタを別の型のポインタとして解釈するために使用できます。

ここでは、

```text
Packetへのポインタ
        ↓
uint8_tへのポインタ
```

という変換を行っています。

つまり、構造体のメモリ領域を「1バイトずつ並んだデータ」として扱います。

### `sizeof(packet)` の意味

```cpp
sizeof(packet)
```

によって、構造体全体のサイズをバイト単位で取得します。

したがって、

```cpp
reinterpret_cast<uint8_t *>(&packet),
sizeof(packet)
```

の組み合わせによって、

> `packet` がメモリ上に持っているデータを、そのサイズ分だけESP-NOWで送信する

という処理になります。

### 他の選択肢

#### 2. `static_cast<uint8_t *>(&packet)`

一般的なポインタ型から無関係なポインタ型への変換には適していません。

#### 3. `&packet`

型が `Packet*` のままで、ESP-NOWが要求するデータポインタの型と一致しません。

#### 4. `packet`

構造体そのものを渡しており、関数が要求するポインタではありません。

# 7. ③ ドット演算子とアロー演算子

### 正解

**3.**

```cpp
header->type
```

### 完成形

```cpp
switch(header->type){
```

### 解説

ここでは、

```cpp
const PacketHeader *header
```

と宣言されています。

`header` は `PacketHeader` 型そのものではなく、**PacketHeaderを指すポインタ**です。

C++では、構造体そのものと構造体へのポインタでメンバへのアクセス方法が異なります。

### 構造体そのものの場合

```cpp
PacketHeader header;

header.type;
```

この場合は `.` を使います。

### 構造体へのポインタの場合

```cpp
PacketHeader *header;

header->type;
```

この場合は `->` を使います。

したがって今回のコードでは、

```cpp
switch(header->type){
```

が正解です。

### `->` の意味

次の2つは基本的に同じ意味です。

```cpp
header->type
```

と

```cpp
(*header).type
```

`->` は、ポインタが指している構造体のメンバにアクセスするための演算子です。

# 8. ④ 受信データの解釈

### 正解

**1.**

```cpp
reinterpret_cast<const DataPacket *>(data)
```

### 完成形

```cpp
const DataPacket *recv_packet =
    reinterpret_cast<const DataPacket *>(data);
```

### 解説

ESP-NOWの受信コールバックでは、

```cpp
void on_data_recv(
    const uint8_t *mac_addr,
    const uint8_t *data,
    int len
)
```

のように、受信データが `const uint8_t*` として渡されます。

つまり、受信したデータはまず、

```text
uint8_tのバイト列
```

として扱われます。

しかし、`DATA` パケットは送信側で、

```cpp
struct DataPacket{
    PacketHeader header;
    StatusData payload;
};
```

という構造になっています。

そこで、受信したバイト列を `DataPacket` 型として解釈するため、

```cpp
reinterpret_cast<const DataPacket *>(data)
```

を使用します。

これにより、

```text
受信したバイト列
      ↓
DataPacketへのポインタとして解釈
      ↓
recv_packet->payload
```

という形でデータを読み取ることができます。

### `const` が付いている理由

受信データのポインタは、

```cpp
const uint8_t *data
```

として渡されています。

これは、受信データを読み取ることはできますが、受信バッファの内容を書き換えることを意図していないことを表しています。

そのため変換後も、

```cpp
const DataPacket *
```

として扱っています。

### 他の選択肢

#### 2. `reinterpret_cast<const Packet *>(data)`

`Packet` 型として解釈してしまうため、`StatusData payload` を含む `DATA` パケット全体を正しく表現できません。

#### 3. `static_cast<const DataPacket *>(data)`

このような無関係なポインタ型への変換には適していません。

#### 4. `data`

`data` は `const uint8_t*` のままなので、

```cpp
recv_packet->payload
```

のような `DataPacket` 固有のメンバアクセスができません。

# 11. 学生に確認させたいポイント

## 11.1 MACアドレスは文字列ではない

例えばシリアル入力では、

```text
AA:BB:CC:DD:EE:FF
```

という文字列として入力されます。

しかし `sscanf()` によって、

```cpp
uint8_t mac_address[6];
```

の6バイトデータへ変換しています。

```cpp
sscanf(mac_string.c_str(),
       "%hhx:%hhx:%hhx:%hhx:%hhx:%hhx",
       &mac_address[0],
       &mac_address[1],
       &mac_address[2],
       &mac_address[3],
       &mac_address[4],
       &mac_address[5]);
```

したがって、Peer登録時には文字列操作ではなくバイト列のコピーが必要になります。

---

## 11.2 構造体はメモリ上ではバイト列

例えば、

```cpp
Packet packet;
packet.header.type = PacketType::PING;
```

とすると、メモリ上には `Packet` の各メンバが配置されています。

ESP-NOWでは、このメモリ領域を、

```cpp
uint8_t*
```

として扱い、指定したサイズ分を送信します。

```cpp
reinterpret_cast<uint8_t *>(&packet)
```

と

```cpp
sizeof(packet)
```

の2つをセットで理解させるとよいポイントです。

---

## 11.3 受信時には送信時と逆の操作を行う

送信側では、

```text
構造体
 ↓
バイト列として送信
```

受信側では、

```text
バイト列
 ↓
構造体として解釈
```

となります。

この対応関係を理解させることが、この実験の重要な学習ポイントです。

# 12. PING / PONGによるRTT測定

`PING` を送信する前に、

```cpp
ping_start_time_ms = millis();
```

として送信時刻を記録します。

相手は `PING` を受信すると、

```cpp
send_pong(mac_addr);
```

によって `PONG` を返します。

`PONG` を受信した側では、

```cpp
const uint32_t elapsed_ms =
    millis() - ping_start_time_ms;
```

として経過時間を計算します。

この値をRTT（Round Trip Time）として表示します。

```text
ESP32 A                     ESP32 B
   │                           │
   │────── PING ──────────────>│
   │                           │
   │<───── PONG ───────────────│
   │                           │
   └── RTTを計算               │
```

RTTは、

> PINGを送信してから、その応答であるPONGを受信するまでの往復時間

です。

# 13. DATA_REQ / DATAによるデータ通信

`DATA_REQ` は、相手にデータ送信を要求するパケットです。

```text
ESP32 A                     ESP32 B
   │                           │
   │──── DATA_REQ ───────────>│
   │                           │
   │                           │ ダミーデータ生成
   │                           │
   │<──── DATA ────────────────│
   │                           │
   └── データ表示              │
```

`send_data()` では、実験用のダミーデータを生成しています。

### 速度

```cpp
packet.payload.speed_cm_s =
    DUMMY_SPEED_MIN_CM_S +
    (send_count % DUMMY_SPEED_RANGE_CM_S);
```

500～999 cm/s程度の値を順番に生成します。

### PWM

```cpp
packet.payload.pwm =
    DUMMY_PWM_MIN +
    (send_count % DUMMY_PWM_RANGE);
```

50～149程度の値を生成します。

### 時刻

```cpp
packet.payload.timestamp_us = micros();
```

送信時のマイクロ秒単位の時刻を記録します。

また、

```cpp
packet.payload.time_to_enter_intersection_us =
    millis() + DUMMY_ENTER_OFFSET_MS;
```

で交差点突入予定時刻を、

```cpp
packet.payload.time_to_exit_intersection_us =
    packet.payload.time_to_enter_intersection_us
    + DUMMY_EXIT_OFFSET_MS;
```

で退出予定時刻を生成しています。

# 16. 注意事項

## 16.1 `reinterpret_cast` は「データ変換」ではなく「解釈」

学生には、`reinterpret_cast` によってバイト列そのものが別のデータへ変換されるわけではないことも説明するとよいでしょう。

例えば、

```cpp
reinterpret_cast<const DataPacket *>(data)
```

は、受信したメモリ領域を `DataPacket` として**解釈するためのポインタを作っている**だけです。

そのため、送信側と受信側で、

- 構造体の定義
- メンバの順序
- 各メンバの型
- データサイズ

などが一致していることが重要です。

---

## 16.2 `len` のチェックは重要

受信処理では、各パケットについてサイズを確認しています。

例えば `DATA` なら、

```cpp
if (len != sizeof(DataPacket)){
    Serial.println("Invalid DATA Packet Size");
    break;
}
```

としています。

これは、受信したバイト数が想定している `DataPacket` のサイズと一致するか確認する処理です。

サイズ確認を行わずに、

```cpp
reinterpret_cast<const DataPacket *>(data)
```

としてしまうと、想定より短いデータを無理に `DataPacket` として扱う危険があります。

8. **DATA_REQ/DATAによって要求―応答型のデータ通信を実現できること**

# 18. 解答まとめ

```text
① 1
   memcpy(peer_info.peer_addr, mac_addr, 6)

② 1
   reinterpret_cast<uint8_t *>(&packet)

③ 3

④ 1

```

という一連のESP-NOW通信処理を構成しています。
